Phobia Relief Therapy in VR

Final Year Project - Viva Guide

Values match the current Unity code. Older docs that still say 20 s / 30 s are stale. Live timers are 60 s baseline and 120 s exposure.

Do not quote Project_Explanation.md or old README timings in the viva. Trust this guide and SessionTiming.cs.

1. One-minute pitch

This is a Virtual Reality Exposure Therapy (VRET) application built in Unity. The patient logs in, sits in a calm baseline room while Polar H10 heart rate and headset movement are averaged for 60 seconds, then an AI decision tree selects Beginner, Intermediate, or Advanced. They pass through a Safe Room, then a 2-minute 360° exposure for heights, darkness, or crowds. Live panic scoring can lower intensity or return them to the Safe Room. Session data is stored locally and synced to Supabase.

Engine: Unity 2022.3.62f3  -  VR: OpenXR + XR Interaction Toolkit  -  Headset: Meta Quest (Quest Link for Polar)  -  Sensor: Polar H10  -  Cloud: Supabase (PostgreSQL + Auth)

2. Polar H10 commands (keep this page handy)

Live heart rate does not come from Unity Bluetooth. A Python script on the same Windows PC reads the strap and sends BPM to Unity on UDP port 7878.

Install once

pip install bleak

If pip is not found:

python -m pip install bleak

Run every demo - leave this window open

cd C:\Users\ahmad\PhobiaReliefTherapy
python tools\polar_hr_bridge.py

Expected output: Scanning... Found Polar H10... Streaming to Unity at 127.0.0.1:7878 then repeating BPM: 78

  1. Quest on Quest Link (USB). USB Link does not need Wi-Fi. Air Link does.
  2. Polar H10 on the chest. Wet the electrodes. Strap snug. Laptop Bluetooth on.
  3. Unity Editor in Play. Leave forceMockSensor false.
  4. Keep polar_hr_bridge.py running the whole session.

Do not promise a standalone Quest APK Polar demo. The bridge talks to 127.0.0.1 on the PC.

3. Sentences to memorize

What is the AI? A rule-based decision tree, not a trained neural network. Inputs are change in heart rate, head movement, and time spent in stress.

Why not Random Forest? RF needs labelled clinical data. A decision tree is deterministic, inspectable, and matches the SRS formula. We kept the word AI because the SRS names this adaptive engine AI.

How is panic detected? PanicScore = 0.5 x dHR + 0.3 x head movement + 0.2 x time spent. Below 10 continue; 10-18 lower stage; 18+ stop / Safe Room.

Starting stage? After baseline, ExposureStageAdvisor maps rest BPM and movement to stage 1 / 2 / 3. Manual Beginner / Intermediate / Advanced is hidden.

Live Polar on APK? No. Panel demo is Quest Link + polar_hr_bridge.py on the laptop.

Appointments? Out of scope. Offline? Yes - local JSON, Supabase when online.

4. How the AI works

Two hand-written C# decision trees. No sklearn, no weights file, no training.

Tree A - starting stage

File: ExposureStageAdvisor.cs

if BPM <= 95 and movement <= 16
    Stage 3  Advanced
else if BPM <= 108 and movement <= 28
    Stage 2  Intermediate
else
    Stage 1  Beginner

Constants in HeartRateBleConstants.cs: StageAdvancedMaxBpm = 95, StageIntermediateMaxBpm = 108. Live Polar rest is typically 70-95 BPM, so a calm seated patient can still get Advanced. AllowManualStageSelection is false.

Viva line: “The AI is a clinical decision tree. Thresholds are physiological, not learned. We can walk through every if-statement.”

Tree B - live recommendations

Files: PanicDetectionService.cs, AdaptiveExposureController.cs. Sampled every 1 second.

ScoreClassAI saysApp action
below 10Calm StressContinue ExposureAfter 20 s calm and 12 s since last change, HUD may suggest advancing next session
10 to 18Panic DetectedRepeat LevelAfter 8 s cooldown, lower stage by 1 (minimum 1)
18+Severe PanicStop / Safe RoomIf score >= 22 and dHR >= 20, and 20 s grace passed, return to Safe Room

dHR > 36 forces score >= 22. dHR > 32 raises a low score to at least 10. Visible AI: UiAiMark badge plus recommendation text.

5. Panic formula (board)

deltaHR     = currentBPM - BaselineHeartRate

HM score    = 0 if movement is not above baseline
            = min(100, (currentMove - baselineMove) / baselineMove x 45)

Time score  = 0 if stress seconds = 0 or deltaHR ≤ 5
            = (stressSeconds / 15) x 100   if under 15 s
            = 100                          if 15 s or more

PanicScore  = 0.5 x deltaHR  +  0.3 x HM  +  0.2 x TimeSpent

A stress second counts when dHR > 16 or movement > 2.4 x baseline movement (floor 15).

Agitation = 0.45 x rotationSpeed + 24 x movementFrequency + 0.35 x jerk

Freeze is tracked but not used in panic. Safety does not fire in the first 20 seconds of exposure. Emergency (not AI): Quest A or X, Editor keyboard X.

14. Likely questions

“This is not AI.” Classical AI includes expert systems and decision trees. The SRS specifies this formula. A black-box Random Forest would be harder to defend with our dataset.

“Show the model file.” There is none. The model is the code in PanicDetectionService and ExposureStageAdvisor.

“Why 360 photos?” One skybox draw, stable 90 Hz, smaller APK. Intensity via _Exposure and three darkness textures.

“Why World Space UI?” Overlay canvases are invisible in the HMD. Scale ~0.001 plus XRI TrackedDeviceGraphicRaycaster.

“Custom keyboard?” Quest OS keyboard sits outside Unity stereo and glitches.

“Double height?” Floor tracking already includes standing height. Origin at 1.7 m stacked to ~3.4 m. Origin Y = 0.

“Coroutines vs Sleep?” Unity is single-threaded. Sleep would freeze the headset. Timers use yield.

15. Honest limitations

  1. Appointments are not in the product.
  2. Live Polar needs the PC bridge + Quest Link, not a standalone APK.
  3. AI is not a trained Random Forest.
  4. Height and crowd use one panorama each; darkness has three images.
  5. Old write-ups say 20/30 seconds. Code is 60/120.
